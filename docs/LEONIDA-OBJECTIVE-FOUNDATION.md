# Leonida objective foundation — Nov 28
Separate candidate, not part of release #315. New namespace, no migration of numbered slots, map pins, manual counts or legacy saves. Start from 12 existing named activity venues and four playable games; these are personal visit/play objectives, not a full collectibles list or a verified game-completion tracker. Source facts carried from atlas450-vi-progress.js and atlas-credits.html#vi-activity-progress. No new location or gameplay verification. No coordinates attached. All IDs are intentionally opaque, manually assigned, permanent; never use row order, name, location or publisher numbering to identify saves. Internal curated aliases are not publisher IDs.
Registry updates must increase revision and check against last accepted registry. Retire rather than remove or repurpose old IDs; preserve aliases forever. Never reuse retired IDs. Save namespace does not depend on source revision. Unknown/retired marks stay in backups, excluded from active statistics. Merge preserves existing positive marks and notes; note conflicts counted. Malformed saves and failed writes are errors; no destructive recovery. LocalStorage pre-write comparison is best effort, not an atomic cross-tab transaction. Future UI must surface unsaved edits, export raw corrupt bytes, listen for storage changes, and use Web Locks or equivalent where available before claiming multi-tab synchronization. No public UI wired in this foundation; next candidate: player-facing search, category progress, queued objectives, item-level details, no coordinate links unless individually supported. Independently verify additional collectible records and completion targets before publication.
